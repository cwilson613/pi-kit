# Project TUI reconstruction and captured terminal acceptance

## Intent

Reconstruct the TUI as a project and harness client of the modular runtime. Preserve useful terminal machinery from the neighboring inline corpus while replacing competing presentation and input owners. Establish captured interaction evidence before changing the shell.

## Scope

First delivery: a deterministic, agent-driven real terminal acceptance runner with isolated state, two streamed turns, resize, and attributable captures. Subsequent deliveries: unified visible/input ownership, stable project/session/work navigation, review evidence, and terminal recovery. Use existing runtime and semantic owners. Do not import the neighboring App monolith or introduce a mandatory daemon.

## Success criteria

- A local scripted run drives the actual executable and captures screens without paid inference.
- A second turn completes after the first, and its answer survives resize.
- The reconstructed shell eventually supports project → session/work → execution/evidence → decision/cancel → conversation without losing client state.
